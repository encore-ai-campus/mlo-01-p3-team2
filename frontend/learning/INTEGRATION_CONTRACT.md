# Python / SQL 학습 연결 계약

기준일: 2026-10-13. 화면은 `frontend/learning/`, 업무·DB·이벤트는 `backend/learning/`과 `backend/eventing/`에 있음.

## 기존 데이터와 제출 식별

문제·세션·답안의 기존 정수 PK를 보존함. 문제와 보기에는 UUIDv4를 추가하고 답안별 `attempt_uuid` 및 사용자별 요청 식별자인 `submission_request_uuid`를 저장함. HTTP 답안 제출에는 UUIDv4 요청 키가 필요함. 같은 요청의 재시도는 저장한 응답을 반환하고, 같은 키로 다른 답안을 보내면 거부함.

## 포인트 저장

`PointWallet`은 기존 플랫폼 사용자 UUID에 연결됨. `PointLedger`는 지급 원장 UUID·답안 시도 UUID·지급 포인트·지급 후 잔액·지급 시각을 저장하며 한 시도당 한 번만 생성됨. 답안·성적·지갑·원장·퀴즈 이벤트·포인트 이벤트·응답 스냅샷을 같은 DB 트랜잭션에 저장함. 동일 사용자의 동시 제출도 잔액 갱신을 직렬화함.

객관식과 빈칸 모두 정답이면 기본 초급 20P·중급 50P·고급 80P를 적립함. API 포인트 상태는 `connected`이며 실제 지급액과 잔액을 표시함. 잘못된 답안·완료된 문제·요청 재시도에는 중복 지급하지 않음. 기존 답안은 보존하고 소급 지급하지 않음. 향후 팀 운영 모델에 옮길 때도 한 DB 트랜잭션과 원장 유일성을 유지해야 함.

## Kafka

학습 열기는 `raw.content_usage / content_open_requested`, 답안은 `raw.content_usage / quiz_answered 1.1`, 실제 지급은 `raw.points / point_granted 1.0`임. 빈칸의 `choice_uuid`는 null, 객관식은 서버가 확인한 보기 UUID임. 제출 원문과 정답 텍스트는 Kafka Raw에 넣지 않음.

Outbox는 서비스 변경과 함께 확정하고 별도 발행기가 ACK를 받은 뒤 전송 완료로 표시함. 재전송은 같은 이벤트 UUID와 페이로드를 유지함. 실제 Kafka 수신에는 팀 수신 서비스의 1.1 계약과 포인트 구독 설정이 필요함. 메시지 구조는 루트 [KAFKA_TOPICS.md](../../KAFKA_TOPICS.md)에 있음.

## 지도와 교실

강의실 1은 Python, 강의실 2는 SQL임. 실제 유리문 출입을 서버가 판정해 개인 학습교실 상태를 열고, 교실의 두 학습 영역에서 E를 누르면 객관식·빈칸 UI를 표시함. 브라우저는 키 입력과 상호작용 요청을 보내고 백엔드가 충돌·교실 출입·학습 영역을 판정함. 학습 팝업 중에는 이동 입력을 비움.

개인 교실 좌표는 메인 층의 좌표와 분리된 화면 상태이며 다른 사용자에게 별도 교실 아바타를 방송하지 않음. 퇴장 시 원래 강의실의 복도 쪽으로 돌아옴. 프론트는 지도 확장 마커에 교실·학습 패널과 해시가 붙은 에셋 URL을 삽입함.

## 문제 데이터 범위

새 문제은행은 Python 40개·SQL 60개, 기존 Python 초급 20개를 보존해 기본 개발 DB 총 120개임. 과목·난이도·유형별 10문제를 제공함. 각 조합당 200개의 전체 문제은행은 아직 완성되지 않았으며 strict full-bank 검증은 그 전까지 실패가 정상임.

구조 검사로 내용의 정확성이나 난이도를 보증하지 않음. 기존 중복 문구는 임의로 다시 작성하지 않으며, Python/SQL 제출 코드를 실제 실행하지 않음.
