# 성능 측정과 사양 조정 기록

2026-10-18 정리: 아래 17대 RAM·126시간 계획은 당시 제안이다. CloudWatch RAM 수집은 이후 취소 기록과 구분하며 현재 상시 실행을 의미하지 않는다. 10월 17일 EC2·PC CPU/RAM/GPU 수집은 로컬 .local/resource-capture-20261017에 남은 별도 일회성 기록이고 현재 중지됐다. 새 성능 수치나 비용을 이 문서 작업에서 생성하지 않았다.

작성일: 2026-10-13. 트래픽과 서버·서비스 성능을 측정한 뒤 사양 변경의 근거와 결과를 기록한다. **아직 실제 측정값이나 승인된 사양 변경은 없다.** 이 문서는 모니터링 설치·자동 사양 조정 스크립트가 아니다.

비용 기록은 같은 폴더의 [일별 실제 비용과 견적](daily-usage.md)에 남긴다. 같은 날짜·계정·서버 이름과 측정 기록 ID를 사용해 두 문서를 연결한다.

## 1. 기록 순서

1. 측정 시간대·대상 서버·현재 사양·배포 버전과 부하 조건을 기록한다.
2. 같은 구간의 CPU·RAM·디스크·네트워크와 서비스 지연·오류·Consumer lag를 수집한다. 수집하지 않은 지표는 미수집으로 표시한다.
3. 병목을 뒷받침하는 지표와 다른 원인 가능성을 기록한다. 측정 전 임의의 임계치를 합격 기준으로 확정하지 않는다.
4. 변경 전후 사양·이유·예상 비용·적용 및 복구 방법을 작성하고 적용 승인을 기록한다.
5. 변경 후 같은 부하 조건으로 재측정하고 비용 문서에 실측 사용액과 비교 기간을 연결한다.

## 5. 모니터링 준비 상태

과거 요청은 **Bastion 제외 서비스 EC2 17대의 RAM 사용률 mem_used_percent를 60초 간격으로 수집하여 Account 1의 서울 리전으로 직접 전송**하는 것이었다. 당시 예상 운영 기간은 2026-10-14 09:00~2026-10-19 15:00 KST, 126시간이다. [비용 문서](daily-usage.md)에 지표·전송 API의 할인 전 견적을 기록했다.

Agent 설치·Account 1 전송용 IAM 역할·네트워크·실제 지표 수신은 아직 미구현·미검증이다. 계정 간 단순 공유 조회와 직접 전송은 다른 방식이며 이번 요구는 직접 전송이다. 설정 적용 후 17대별 지표 구분·60초 수집·중복 시계열 여부를 확인하고 비용 및 준비 상태를 갱신한다. 수집되지 않는 값은 미수집으로 유지한다.
