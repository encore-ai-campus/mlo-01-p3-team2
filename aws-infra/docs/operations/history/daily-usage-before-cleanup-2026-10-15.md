## 1. 기록 기준

- **날짜가 바뀌어도 전날 기록을 삭제하거나 덮어쓰지 않는다.** 새 날짜의 실제 비용 행과 견적 기록을 추가하고, 기존 날짜의 정정은 원본·정정일·변경 사유를 함께 남긴다.
- 견적 원문은 `docs/costs/history/YYYY-MM-DD.md`로 보존한다. 같은 날짜에 추가 계산이 생기면 기존 내용을 유지하고 새 견적 ID로 덧붙인다. 별개의 사용 시나리오를 실제 일별 지출처럼 합산하지 않는다.
- 비용 대상 날짜와 조회 시각을 분리한다. 조회 시각은 시간대까지 기록하고, 대상 날짜는 사용한 청구 화면의 기간·시간대 기준을 남긴다.
- 통화는 USD를 기본으로 한다. 원화는 적용 환율·세금 가정을 함께 적는다.
- 당일 사용액과 월 누적액은 같은 비용 지표·필터로 조회하고 지표명, 리전/서비스 범위, 세금·크레딧 포함 여부를 출처에 남긴다. 전 계정 총비용과 서울 리전 자원 견적의 범위를 구분한다.
- 크레딧 잔액은 사용액과 별도 기록한다. 최초 지급액을 현재 잔액으로 간주하지 않는다.
- 미조회 값은 `미조회`로 둔다. 0달러로 쓰거나 아래 견적을 실측란에 옮기지 않는다.
- 청구 데이터가 이후 갱신되면 조회 시각과 수정 이유를 남긴다. 관련 성능 기록 ID와 링크를 비고에 연결한다.

### CloudWatch 계산 조건과 구현 상태

- 확정한 요구: Bastion 제외 서비스 17대에서 RAM 사용률 `mem_used_percent` 한 종류를 60초 간격으로 수집하고 Account 1의 서울 리전으로 직접 전송한다. Bastion EC2 실행 비용은 기본 소계에 포함한다.
- 서버를 구분하는 차원 조합을 하나씩 사용하여 지표 시계열을 총 17개로 가정한다. 추가 RAM 지표·집계 차원·중복 전송은 포함하지 않는다. 1분마다 측정해도 매번 새로운 지표가 생긴다는 뜻은 아니다.
- API는 서버마다 1분에 PutMetricData 요청 1회를 보낸다고 가정하여 128,520회를 계산했다. 실제 Agent의 배치·전송 주기·재시도에 따라 요청 수는 달라진다. 측정 간격만으로 요청 수가 확정되지는 않는다.
- 서울 공개 단가는 사용자 지정 지표 월 0.30 USD/개(첫 10,000개 구간), 일반 API 요청 1,000회당 0.01 USD다. 월 지표 비용은 10월 744시간 중 126시간으로 비례 계산한다.
- AWS 가격표의 무료 지표 10개·일반 API 요청 월 100만 회 제공량은 적용 자격·기존 사용·공유 범위를 조회하지 않았으므로 소계에서 차감하지 않았다. 적용되면 실제 추가 비용은 줄어들 수 있다. 실제 청구액이나 비용 상한을 보장하는 값은 아니다.
- 추가 알람·유료 대시보드·로그 수집·GetMetricData 등 조회 API·추가 통신/Endpoint 비용은 제외했다. Agent 설치, Account 1 전송용 IAM 역할·네트워크와 지표 수신 검증은 아직 수행하지 않았다. AWS 전체 통합 결제도 설정하지 않았다.

> ## 다시 계산하는 방법
>
> 서버 실행 시간과 디스크·ALB·IP 유지 시간을 각각 넣는다. 예를 들어 EC2를 하루 9시간만 켜더라도 EBS·ALB·EIP를 그대로 두면 이 자원들은 24시간으로 계산한다.
>
> ```text
> EC2 비용 = 각 사양의 수량 × 시간당 단가 × 실행 시간의 합
> EBS 비용 = 각 볼륨의 GiB × 월 단가 × 유지 시간 / 해당 월 전체 시간의 합
> ALB 기본료 = ALB 수량 × 시간당 단가 × 유지 시간
> ALB 처리료 = 시간별 사용 LCU × LCU 시간당 단가의 합
> 공인 IPv4 비용 = 주소별 사용 또는 할당 유지 시간 × 0.005의 합
>
> 기본 소계 = EC2 + EBS + ALB 기본료 + ALB 처리료 + 공인 IPv4
> 확장 소계 = 기본 소계 + 유료 전송량 + S3 + 로그 + 백업 + 추가 서비스
> 원화 세전 = USD 소계 × 적용 환율
> 세금 10% 가정 금액 = 원화 세전 × 1.10
> ```
>
> ALB의 1시간 미만 사용은 기본료 계산에서 한 시간으로 올림된다. EBS 유지 기간이 여러 달에 걸치면 각 달의 일수와 사용 시간을 나누어 합산한다. 크레딧은 계정별 적용 대상과 잔액을 확인한 뒤 반영한다. [ALB 과금 설명](https://aws.amazon.com/elasticloadbalancing/pricing/), [EBS 시간 비례 계산 예시](https://aws.amazon.com/ebs/pricing/)
>
> 트래픽이 생기면 사용자 수만 넣지 말고 ALB LCU, 인터넷 송신 GB, AZ 교차 통신량을 실제 사용량으로 추가한다. gp3의 기본 성능보다 높은 IOPS·처리량을 설정하거나 스냅샷을 보관하는 경우에도 별도 단가를 추가한다.
