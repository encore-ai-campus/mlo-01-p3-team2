## 조사 방법과 한계

- 광고주센터는 로그인해야 들어갈 수 있어서 **실제 화면은 직접 보지 못했다.** 광고 대행사 블로그(마케팅 인사이드)가 공식 화면을 캡처해 올린 가이드 두 편의 이미지를 브라우저로 열어 확인했다.
- 화면 이미지는 네이버·원 게시자의 저작물이라 **이 저장소에 복사하지 않고 링크만 둔다.** 아래 설명은 보고 정리한 것이다.

## 1. 구조 관찰

### 1.1 전체 틀

- 상단 바: 로고, 검색창, 계정 정보, 로그아웃. 왼쪽에는 세로 메뉴(**대시보드 / 전체 캠페인 / 광고 관리 / 보고서 / 도구 / 구성요소 관리**)와 눈에 띄는 **"광고 만들기"** 버튼이 있다.
- 광고 계층은 **캠페인 → 광고그룹 → 소재**다. 캠페인은 목적·기간·예산, 광고그룹은 타겟·게재 위치·입찰, 소재는 실제 노출 내용을 정한다.

### 1.2 대시보드(첫 화면)

- 상단에서 **기간을 고른다.**
- 지표 카드 3개: 총 비용 / 클릭수 / 전환수. 카드마다 직전 기간 대비 증감률(%)이 붙는다.
- 카드 아래 **지표별 추세 꺾은선 그래프**(날짜별).
- 하단 왼쪽에 **지표 상위 캠페인 표**(캠페인명, 총 비용, 평균 대비 증감, 전환율), 오른쪽에 잔액 위젯.
- 화면 오른쪽에 **인사이트 패널**(탭: 모두 보기/추천/운영/프로모션). 예산 소진, 소재 보류 같은 **운영 알림**이 쌓인다.

### 1.3 전체 캠페인 목록

- 기간 선택 + 지표 선택(노출수, 평균 클릭률 등) 추세 그래프.
- 표 열: **ON/OFF 토글**, 광고 구분, 캠페인 이름(링크), 캠페인 유형, 노출수, 클릭수, 클릭률, 평균 CPC, 총 비용, 총 전환수. 맨 앞에 선택 체크박스.
- 표 위 도구: 검색, **열 맞춤 설정, 상세 데이터, 엑셀 다운로드**, **+ 광고 만들기**.
- **켜고 끄는 동작이 목록 안의 토글 하나**로 끝난다. 광고주가 가장 자주 하는 일이 목록에서 바로 된다.

### 1.4 광고 만들기 (GFA 기준, 단계형)

1. **캠페인 목적 선택**: 카드 7장(웹사이트 전환, 인지도·트래픽, 앱 전환, 동영상 조회 …). 목적에 따라 뒤 단계의 옵션이 달라진다. 하단에 안내 문구.
2. 캠페인 이름 등 기본 설정 폼(필수 항목 앞에 체크 표시, 드롭다운마다 도움말 문구와 바로가기 링크).
3. **광고그룹**: 이름 입력(글자수 카운터 `0자/128자`), 타겟(연령·지역·관심사), 디바이스·게재 위치(**"모두 선택" / "직접 선택" 라디오**, 아래 회색 안내 박스).
4. **입찰 및 예산**: 입찰 방식(자동 / **수동**), **비용 관리(입찰가 한도 입력, 한도 없음 옵션)**, **청구 기준 드롭다운(CPC, CPV 등)**.
5. 소재 등록(별도 단계). 이미지 비율·텍스트 비율 등의 규격 안내가 붙는다.

### 1.5 공통 UI 패턴

- 입력 항목 옆의 안내문이 많다("변경 시 학습이 초기화되므로 잦은 변경은 지양"). **되돌릴 수 없는 영향은 입력 칸 바로 아래 문장으로 경고한다.**
- 폼은 카드형 섹션으로 구분되고, 섹션마다 제목과 구분선이 있다.
- 숫자 입력은 단위(₩)를 칸 안에 붙인다.

## 2. 우리 화면으로 옮기기 [제안]

우리는 외부 결제는 없지만 **포인트 지갑, 일예산, 광고그룹(게재 위치·입찰)** 이 있다. 빼는 것은 **타겟팅**뿐이고, 이후 붙일 자리는 남긴다(설계 §6.4).

| 네이버 | 우리 | 이유 |
|---|---|---|
| 캠페인 → 광고그룹 → 소재 | **그대로** (캠페인 → 광고그룹 → 소재) | 게재 위치마다 금액·방식이 달라 위치와 입찰을 묶는 단위가 필요 |
| 캠페인 목적 카드 | 광고 만들기 첫 단계: **과금 단위(노출/클릭/전환) 선택 카드** → 그 단위의 게재 위치 목록이 뒤 단계에 나온다 | 슬롯은 과금 단위를 하나 가지고, 광고그룹의 위치는 같은 단위끼리만 묶인다 |
| 광고그룹: 타겟 설정 | **없음.** 광고그룹 폼에 섹션이 추가될 수 있는 구조로만 둔다 | 타겟팅은 이후 |
| 광고그룹: 게재 위치 ("모두 선택 / 직접 선택") | **게재 위치 체크 목록.** **매체(플랫폼)별로 묶어서** 보여주고, 위치마다 **현재 노출 범위(하한~상한)와 기준가**를 같이 표시한다. 과금 단위가 다른 위치는 선택할 수 없게 비활성 처리 | 위치별로 금액이 다르다 |
| 입찰: 수동 입찰, 입찰가 한도 | **입찰 금액 입력.** 칸 아래에 선택한 위치별 적용 결과를 보여준다("A: 30 적용 / B: 20(상한) 적용 / C: 현재 하한 미만이라 노출되지 않습니다"). **입력은 막지 않는다** | 입찰 정책(설계 §4.1~4.2)과 직결 |
| 일 예산(캠페인) | **일예산 입력**(필수), 캠페인 화면에 "오늘 소진 / 남은 예산", 리셋 시각 안내(KST 09:00) | 예산 구현. 일 경계는 UTC |
| 비즈머니(잔액·충전) | **포인트 지갑**: 대시보드 위젯(잔액, 오늘 소진, 소진 바)과 원장 내역 페이지. 충전 버튼은 없다(가입 지급과 관리자 조정만). 메타버스 연계(C5) 때 추가 | 설계 §4.7 |
| 청구 기준(CPC·CPV) | 과금 단위 선택(생성 후 변경 불가라고 명시) | 설계 §4.2 |
| 대시보드 지표(비용·클릭·전환) | **노출수·클릭수·전환수 + 소진 포인트** + 증감률 + 추세 그래프 | 우리 반응 3종과 포인트 |
| 전체 캠페인 목록 + ON/OFF 토글 | 그대로. 캠페인·광고그룹 모두 토글. 상태 배지(`ACTIVE`/`PAUSED`/`SUSPENDED`/`ENDED`)를 같이 표시. **`SUSPENDED`는 토글 비활성 + 사유 표시.** 예산 소진·잔액 부족은 상태가 아니므로 보조 표시("오늘 예산 소진, 내일 09:00 재개") | 관리자 중단 사유 열람. 소진은 조건이다 |
| 인사이트 패널(운영 알림) | **알림 패널**: "관리자에 의해 중단되었습니다(사유)", "기간이 끝났습니다", "일예산을 모두 사용했습니다", "포인트 잔액이 부족합니다", "입찰이 상한을 넘어 상한으로 적용 중", "정책이 바뀌어 입찰이 하한 미만이 되어 노출되지 않습니다" | 운영 이벤트 노출. 가장 작은 형태로 |
| 열 맞춤·엑셀 다운로드 | V1 제외 (CSV 다운로드는 필요해지면) | 최소 범위 |

| 포인트 | 잔액, 원장 내역(지급·과금·조정), 반응별 과금 내역 |
| 내 정보 | 닉네임·반 수정, 비밀번호 변경 |

### 관리자 화면 목록 [제안: Django admin 기반]

네이버에는 관리자 쪽 화면이 보이지 않으므로(광고주센터는 광고주용) 벤치마킹 대상이 아니다. 광고주 화면의 표·배지 규칙을 맞춰 아래를 만든다.

| 화면 | 내용 |
|---|---|
| 입찰 정책 | 슬롯 목록(과금 단위 표시). **수정은 새 버전 입력 폼**(현재값이 채워진 채 열림, 변경 사유 필수). 이력 열람. 하한≤기준가≤상한 검증. **목록에서 여러 슬롯을 선택해 같은 값으로 새 버전을 한꺼번에 입력하는 일괄 동작**(매체가 늘어날 때 대비). 슬롯별 버전은 각자 따로 쌓인다 |
| 광고 모니터링 | 최근 등록·변경된 캠페인 목록 + **소재 썸네일**, **이동 주소 도메인(눈에 띄게)**, 광고주 닉네임·반. 검수가 목적이라 이미지와 도메인이 한눈에 보여야 한다 |
| 중단/해제 | 목록 일괄 동작 + 사유 입력. 감사 로그에 남는다 |
| 광고주 계정 | 비활성화, 비밀번호 초기화, 캠페인·소재 수와 업로드 용량 상한 확인 |
| 지갑·원장 | 광고주별 잔액, 원장 열람(읽기 전용), **포인트 조정**(사유 필수, 반대 부호 항목으로 기록) |
| 매체·슬롯 | 등록·비활성, 슬롯의 과금 단위, 소재 규격 |
| 감사 로그 | 읽기 전용 |

## 3. 화면 설계에서 따를 규칙

1. **자주 하는 일은 목록에서 바로**(켜기/끄기).
2. **되돌릴 수 없거나 영향이 큰 입력 칸 아래에 경고 문장을 둔다**(과금 단위 변경 불가, 상한 적용, 하한 미만 비노출).
3. 입력 칸 옆에 **규격을 미리 보여준다**(위치별 하한·기준가·상한, 이미지 형식·용량).
4. 위험한 동작(관리자 중단, 포인트 조정)은 **사유 입력이 필수**다.
5. 광고주에게 `subject_id` 등 노출 대상 정보는 어떤 화면에도 보이지 않는다.
6. **시각은 KST로 표시**하되 UTC 기준으로 동작하는 항목(일예산 리셋)은 화면에 리셋 시각을 적는다.
7. 포인트·예산 수치는 항상 단위(포인트)를 같이 적는다.
8. 화면은 계약 C1·내부 모델을 바꾸지 않고 `api`로만 호출한다(설계 R2).
