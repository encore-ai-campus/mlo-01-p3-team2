# PLAYDATA 캠퍼스 메타버스

문서 기준: 2026-10-15. 화면을 담당하는 프론트와 인증·업무·DB·실시간 판정을 담당하는 백엔드를 분리한 버전임.

## 실행

저장소 루트에서 공용 가상환경을 준비한 뒤 두 서버를 함께 실행함.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run-split.py
```

브라우저는 **http://127.0.0.1:8004/** 로 접속함. 백엔드는 기본 **127.0.0.1:9003**에서 실행함. `run-local.cmd`와 `run-develop.cmd`도 같은 분리 실행기를 사용함. Ctrl+C로 두 서버를 종료함.

최초 실행은 DB 마이그레이션을 적용함. 기존 DB를 사용하는 방법, 별도 실행, 내부망 접속과 환경 변수는 [RUN_GUIDE.md](RUN_GUIDE.md)에 정리함. 기존 루트 `manage.py`는 백엔드 관리 명령 호환용임. 루트 `run-campus.py`는 백엔드만 실행하므로 지도 화면은 프론트 서버로 접속해야 함.

  dist/                 18층·옥상 지도, 캐릭터, 채팅·게시판·부스 UI
  learning/             학습교실과 문제·결과 UI
  tests/                지도·화면 JavaScript 검증

  accounts/             계정·과정·아바타·로그인 정책

  learning/             문제·답안·성적·포인트 지갑과 원장

프론트는 DB와 인증 세션을 소유하지 않음. 화면에 필요한 JSON을 백엔드에서 받아 렌더링하고 HTTP 요청의 쿠키·CSRF·본문 및 WebSocket 메시지를 중계함. 백엔드는 비밀번호 검증, 권한, 세션, 이동·충돌·층 전환·교실 및 부스 접근을 판정함. 브라우저는 키 입력을 보내고 승인된 좌표를 부드럽게 표시함.

`backend/ad_bridge/`는 게임에서 실행하는 광고 브리지다. 앱·API가 등록돼 있으며 `ADS_ENABLED=1`과 슬롯 설정 후 활성화된다. 옥상 공통 회차·포털 좌우 광고·매체 키 분리·50% 이상 연속 1초 노출과 운영 설정은 [광고 모듈 안내](backend/ad_bridge/README.md)를 참고한다.

## 현재 기능

- 18층과 옥상의 2.5D 아이소메트릭 지도, 방향키·WASD 이동, 실시간 아바타와 전체 접속자 표시.
- 한글·영문·IME 입력 상태에서도 물리 키 기준 WASD·E·Z를 처리함. 채팅·입력창의 글 입력과 단축키는 유지함.
- 응답이 끊긴 WebSocket은 다시 연결하고, 같은 로그인 세션의 새 연결은 이전 연결을 교체함. 중복 캐릭터를 남기지 않으며 현재 위치와 개인 학습교실 상태를 이어받음.
- 일반 사용자 150% 고정, 관리자 35~360% 줌과 화면 고정 전환. 미니맵 대신 우하단 게시판 접근창 제공.
- 과정별 회원가입과 닉네임·아바타 설정. MLO 1·2·3기는 남자1·여자2, SKN 34·36기와 AIO 4기는 남자2·여자1 중 선택하고 이후 임의 변경을 제한함.
- 로그인 최대 8시간·비활동 30분, 만료 1분 전 안내, 마지막 위치 저장과 WebSocket 종료, 하루 한 번 만료 세션 정리. 다른 브라우저의 새 로그인은 이전 로그인을 종료함.
- 유리문·창고 슬라이드문 열림 상태 공유, 통합 3·4 강의실의 PLAYDATA 대형 게시판, 구내식당 메뉴와 엔코아 타임 커뮤니티.
- 구내식당 사진은 카카오 채널 프로필에서 한국 시간 오전 10시에 갱신함. 점메추는 8개 음식 분류 중 서버가 선택한 결과를 돌림판으로 표시함.
- 커뮤니티 전체글·공지·자유·IT·프로젝트·취업·자료·질문 탭, 검색·페이지 이동, 본인 글·댓글·대댓글 수정·삭제와 관리자 관리.
- Enter로 채팅 입력, 좌하단 채팅과 5초 말풍선, 10초 새 메시지가 없으면 채팅 fade-out. 설정에서 채팅·말풍선·다른 사용자 닉네임 표시를 전환함.
- 계단·포탈 층 이동, 예/아니오 방향키 선택, 3초 `loading...` 동안 이동 차단. 옥상 도시 배경·분수 유지, 콘텐츠 부스는 전용 에셋으로 표시하고 이벤트 배너는 높은 벽면에 부착함. 별도 광고 게시판은 광고용 공간으로 유지함.
- 게임 카드 16개와 심리 테스트 링크. 외부 사이트의 임베드·브라우저 정책에 따라 별도 창으로 열며, 외부 게임 결과를 수집하지 않음.
- 유튜브 부스는 YouTube 홈페이지를 별도 브라우저 팝업으로 열고 팝업 차단 시 다시 열기 링크를 표시함.
- 옥상 부저 → Google 설문 → 실제 제출 확인 후 참가 등록. 관리자 이벤트 일정·무작위 추첨, 전체 사용자에게 동일한 슬롯 추첨 결과 표시.
- 당첨 계정은 이벤트 창과 추첨 결과에서 카카오톡 오픈채팅 QR 수령 안내를 확인함. 관리자는 이벤트 관리에서 QR을 등록·미리보기하고, QR 이미지는 DB에 저장하며 당첨자·관리자 권한으로 제공함. 기프티콘 전달은 운영자가 안내된 채팅에서 진행함.
- 강의실 1의 Python·강의실 2의 SQL 학습교실. 객관식·빈칸, 난이도별 10문제, 문제당 최대 3회, 진행 복원·성적·오답 복습 지원.
- 학습교실 입장 후 2초 출입 대기와 진입 키 재입력을 적용함. 개인 교실의 사용자는 공용 지도에 표시하지 않으며 공용 유리문 조작을 방해하지 않음.
- Z키를 누르거나 찌르기 버튼을 누르면 앞의 가까운 캐릭터에게 손 동작·반응 효과를 표시함. 길게 누르면 0.25초 간격으로 반복하며 놓기·화면 전환·연결 종료 시 멈춤. 메인 맵은 가까운 같은 층 사용자에게 공유하고 개인 학습교실 NPC 반응은 본인에게 표시함. 좌표·충돌·거리·방향을 서버가 판정하며 위치·포인트를 바꾸지 않음.
- 줌 조작 옆에 보유 포인트를 표시하고 클릭하면 본인의 적립 내역을 최근순 10건씩 조회함. 학습 정답 지급 후 잔액과 증가 효과를 갱신하며, 목록 조회는 포인트를 새로 지급하지 않음.
- 학습 정답 포인트: 초급 20P·중급 50P·고급 80P. 답안·지갑·지급 원장·Outbox를 함께 저장하며 동일 제출의 재시도로 중복 지급하지 않음. 기존 답안은 소급 지급하지 않음.

추가 게임은 테트리스, 세상에서 가장 어려운 게임, 죽림고수, 검 강화하기, 황새와 오래 걷기, 아이작, 팔라독, 솔리테어임. 기존 8종과 같은 게임 카드·외부 콘텐츠 열기 경로를 사용함. Python/SQL 교실에는 학습 영역 안내와 강사·학생 캐릭터 표현을 개선함.

## 데이터와 Kafka

로컬 개발 기본 DB는 **backend/db.sqlite3**, AWS 운영 DB는 **MySQL `playdata_campus`**임. `DATABASE_ENGINE`과 MySQL 연결 변수로 구분함. `CAMPUS_DATA_DIR`는 SQLite DB·실행 파일의 위치를 지정함. 계정·위치·게시글·채팅 보관 원문·설문 참가·학습 기록·포인트·Outbox를 저장함. 실제 DB·연결 키·식단 캐시·가상환경은 Git에 올리지 않음.

총 **7개 토픽, 15개 이벤트**를 정의함. `quiz_answered`는 객관식과 빈칸을 포함한 스키마 **1.1**, 나머지는 **1.0**임. 토픽·필드·저장과 재시도 규칙은 [KAFKA_TOPICS.md](KAFKA_TOPICS.md)에 정리함.

이동 좌표는 변경된 사용자의 최신 위치를 약 **5초마다** 저장하며 같은 트랜잭션에 `movement_observed` Outbox를 기록함. 방향만 바뀌면 복원용 방향은 저장하지만 이동 이벤트를 만들지 않음. 층 이동·종료·로그아웃·만료는 마지막 변경 위치를 즉시 저장함. WebSocket 화면 동기화는 더 짧은 주기로 유지함.

Outbox가 비어 있으면 조회 간격을 최대 5초까지 늘리고, 같은 서버에서 새 이벤트가 커밋되면 즉시 발행기를 깨움. MySQL 발행기 스레드만 DB 연결 하나를 기본 60초 동안 재사용하며 HTTP·WebSocket의 연결 정책은 유지함. 다른 프로세스가 기록한 이벤트도 주기 조회로 확인함.

브로커 주소가 비어 있으면 이벤트는 DB Outbox에 대기함. 실제 전송에는 백엔드 Kafka 설정, 사전 토픽 생성, 수신 서비스의 `quiz_answered 1.1`·`raw.points` 지원이 필요함. 2026-10-14 AWS에서 브로커 3대·7개 토픽·Outbox 발행 완료와 실제 Kafka 메시지를 확인함. 2026-10-15 AWS 운영 DB를 MySQL로 전환함. 기존 운영 데이터 1,908건을 좌표·시간 정밀도까지 보존해 대조했고, MySQL 3대의 계정·포인트 복제와 공개 접속을 확인함. SQLite와 기존 설정은 비공개 백업에 보관함. 수신 파이프라인 처리·MongoDB·운영 광고 연결은 별도로 검증해야 함. 위치와 Raw Outbox의 JSON은 MySQL에서 원문을 보존하는 LONGTEXT와 JSON 유효성 검사를 사용해 좌표의 끝자리와 Kafka fingerprint가 바뀌지 않도록 함. API·Kafka의 JSON 구조와 스키마 버전은 유지함.

현재 실시간 접속과 문·이벤트 방송은 **단일 백엔드 프로세스의 메모리 상태**를 사용함. 여러 백엔드 프로세스로 확장하려면 공유 상태와 채널 계층을 별도로 연결해야 함.

## 검증

백엔드 기능·파일 DB 동시성 검증, 프론트 HTTP 중계·렌더링 검증, 지도 JavaScript와 학습 UI 검증을 제공함. 실행 명령과 데이터 보존 절차는 [실행 가이드](RUN_GUIDE.md#검증)에 정리함.


### 2026-10-15 이용 안내·맵 UI 갱신

- 신규 회원은 닉네임·아바타 설정 뒤 최초 이용 안내를 받음. 완료·건너뛰기 상태를 운영 DB에 저장하며 설정에서 다시 열 수 있음. 기존 설정 완료 계정은 배포 마이그레이션에서 확인 완료로 처리함.
- 맵을 브라우저 창 전체에 표시하고 계정·설정·이동 키 안내를 하단으로 이동함. 공간 안내는 좌측 상단 버튼에서 접고 펼침.
- 18층 바깥 배경을 베이지색 아이소메트릭 배경으로 정리함. 강의실 유리문 7개를 제거하고 출입구를 바로 통과하도록 서버 충돌 판정도 맞춤. 창고 슬라이드문은 유지함.
- 층 전환의 3초 이동 차단은 유지함. 계단에서는 캐릭터의 오르내림, 포탈에서는 순간이동 애니메이션을 표시함.
- Python 초급 빈칸 10문항의 설명만 명확히 수정함. 문제 UUID·정답·기존 응답·포인트·Kafka 이벤트 형식은 유지함.
- 적용 마이그레이션: accounts 0008_profile_guide_completed, learning 0004_beginner_prompt_wording.


### 개인 쪽지함과 조작 변경 (2026-10-16)

- CAMPUS_DM_ENABLED=1로 켜면 프로필 설정을 마친 계정이 닉네임으로 상대를 검색하고 쪽지를 보내거나 답장할 수 있음. 상대가 오프라인이어도 DB에 보관됨.
- 대화 목록·미확인 수·최근 메시지·읽음 상태를 제공함. 대화 당사자만 조회·읽음 처리가 가능하며 관리자도 다른 사람의 대화를 조회할 수 없음.
- 쪽지 본문은 개인 쪽지 테이블에 저장함. 기존 전체 채팅과 구분하며 Kafka/Outbox에 쪽지 본문이나 새 이벤트를 추가하지 않음. 웹소켓에는 대화 갱신 알림만 전달함.
- Space 또는 하단 버튼으로 점프함. 같은 층 접속자에게 모션을 공유하고 학습교실에서는 본인 화면에 표시함. 바닥 좌표·충돌·이동 수집 간격은 유지함.
- 일반 사용자의 맵은 150%로 고정함. 관리자에게는 35~360% 줌과 화면 고정 전환을 유지함.
