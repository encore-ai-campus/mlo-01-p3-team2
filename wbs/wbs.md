## 1. 작성 기준

팀원 5명의 담당 영역에 맞춰 실제 수행한 작업을 영역별 6개, 총 30개 작업으로 묶었다. 각 작업에는 산출물, 관련 PRD 요구사항, 실제 작업 이력과 병합일을 연결했다. 작업 개수를 맞춘 것이므로 영역별 작업량이나 투입 시간이 같다는 뜻은 아니다.

GitHub 최신 브랜치·PR 63개·일반 이슈 54개를 조회하고, 원격 `dev`와 SHA가 일치하는 로컬 Git 객체의 코드·계약·문서를 30개 작업과 대조했다. PR·이슈 본문의 검증 결과는 작성 당시의 기록으로 인용한다. 이번 검토에서 애플리케이션 테스트나 운영 서버 점검을 새로 실행하지는 않았다. 아래의 **병합 확인**은 실제 반영을 확인한 이력이다. 인프라 후속 변경은 병합된 것을 전제로 상태를 작성하고, 확인되지 않은 병합일은 `—`로 표시한다. 병합 상태와 배포·운영 검증 결과는 구분한다.

| 표기 | 의미 |
|---|---|
| 병합 확인 | GitHub PR의 `merged_at`으로 대상 브랜치 반영을 확인함. 별도 표시가 없으면 `dev` 기준. |
| 검증 기록 있음 | 해당 PR·이슈 본문에 작성자의 시험 또는 운영 확인 결과가 있음. 이번 작업에서 재현한 결과는 아님. |
| 추가 확인 | 현재 운영 적용 여부, 정책 또는 전체 흐름에 대한 근거가 더 필요함. |
| 미병합 | 확인 시점에 해당 PR이 아직 병합되지 않음. |

날짜는 한국 표준시(KST)로 표시한다. **병합일은 실제 작업 시작일·종료일이나 배포일을 대신하지 않는다.** 전체 수행 기간과 작업별 계획일·공수는 확인된 자료가 없어 미입력으로 둔다. BRD의 `2026-10-19`는 서비스 공개 목표이며 작업 완료 실적으로 사용하지 않는다.

후속 작업은 `infra;#45@7f6108562a5d5785983c4393d2b748d2011282a5`의 [운영 구성][infra-current]과 [도메인 설정 변경][infra-followup]을 기준으로 추가했다. PRD와 같이 해당 변경의 `dev` 통합을 전제로 하며, 기존 #90의 병합·검증 기록을 후속 변경의 병합·배포 증적으로 사용하지 않는다.

게임·광고 앱의 프론트/백엔드 분리와 앱 실행 구성은 1.6 및 3.3절의 광고 서비스 작업 이력으로 관리한다. MySQL 전환 시 기존 업무 데이터 대조는 1.6의 캠퍼스 작업이며, 인프라의 DB 클러스터 설치·저장 경로·복구 절차와 연결한다. 광고 오류 로그 출력과 파이프라인 재처리도 각각 광고·파이프라인 영역의 작업이다.

Monitoring 역할 코드는 존재하지만 [Ansible 실행 코드][platform-site]는 `monitoring` 그룹이 있을 때만 적용한다. [설치 문서][platform]의 과거 구성 검증을 현재 환경의 통합 모니터링 구축 완료로 표시하지 않는다. `FR-OPS-002`의 감시·알림 범위는 5절의 추가 확인 작업에서 관리한다.

Bastion은 EIP를 사용하며 WBS 5.2의 구성은 유지한다. 후속 인프라 README도 EIP 설명으로 수정됐으므로 과거의 자동 공인 IP 설명 불일치는 현재 미해결 항목에서 제외한다. 데이터 볼륨 마운트·현재 운영 상태의 확인 경계는 [전체 검토 기록](./review.md)에 남겼다.

## 6. 관련 문서 작업 이력

문서 작업은 다섯 영역에 공통으로 연결되는 산출물이며 별도의 여섯 번째 담당 영역을 만들지 않는다.

| 산출물 | 기록 작성자 | 근거 | 확인 시점 상태 |
|---|---|---|---|
| BRD | 강한솔 | [#111][p111], 후속 [#112][p112] | #111: `doc` 병합 2026-10-17 / #112: 미병합 |
| PRD | 조성현 | [#116][p116], [현재 로컬 PRD](../docs/prd.md) | 기존 조회 시 #116: 미병합 / 현재 로컬 v0.10을 WBS 요구사항 연결에 사용 |
| DRD·광고 API 문서 | 김남동 | [#115][p115] | 미병합 |
| WBS | 작성자 기입 필요 | 본 문서 | 신규 초안 작성. 커밋·PR 미생성 |

이슈가 열려 있어도 관련 PR이 병합됐으면 구현 이력에는 병합 사실을 반영한다. 예를 들어 학습 [#40][p40]·[#108][p108]과 분수 [#109][p109]는 병합돼 있다. 반대로 닫혔지만 병합되지 않은 대체 PR은 완료 실적으로 세지 않는다.

## 7. 업데이트 방법

1. 작업이 바뀌면 기존 WBS ID의 세부 작업·산출물을 갱신하고 해당 PR을 연결한다.
2. 운영 적용 또는 시험을 확인하면 환경·커밋·확인일·결과가 있는 기록을 추가한다. PR 병합일과 구분한다.
3. 추가 확인 항목을 끝내면 5절에 결과 링크와 실제 확인일을 기록한다.
4. 실제 시작일·종료일·공수를 확보하면 일정표를 추가한다. 이슈 생성일이나 병합일로 임의 대체하지 않는다.

캠퍼스·광고 포인트 전환, 자동 추천·개인화, 자동 입찰, 다중 AZ 확장은 PRD의 보류 범위를 유지한다. 새로 수행하기로 결정한 경우에만 작업과 완료 기준을 추가한다.
